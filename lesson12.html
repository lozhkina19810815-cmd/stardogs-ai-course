Отдельная мысль урока — как защититься от ситуации, когда встроенное у вас уже работает, а вы его не знаете и пытаетесь построить надстройку поверх. Пример из нашей практики — Auto-memory: 38 дней её вёл сам агент, я не знала и учила в курсе делать руками. Подробности — в кейсе ниже.

После урока вы сможете: различать что встроено в Claude Code и что мы добавили сверху; включить план-режим перед сложной задачей; разгрузить контекст через под-агента; понять, какие папки настроек у вас уже есть и зачем; не пугаться, если на Mac агент пишет «работаю в worktree».

Уточнение про «инструмент»

Здесь речь про Claude Code, не про Claude вообще.

«Claude» — это семейство продуктов Anthropic. У них есть claude.ai — браузерный чат, как ChatGPT. У них есть Claude API — программный доступ для разработчиков. И у них есть Claude Code — продукт для работы с кодом и проектами через несколько интерфейсов: терминал (CLI), Desktop-приложение для Mac/Windows, плагины для VS Code и JetBrains, web-режим claude.ai/code, мобильный мост. Я работаю с Ириной в основном через терминал и Desktop, по корпоративной подписке Cowork (она даёт нам особенности вроде автоматического worktree). Это разные продукты с разными интерфейсами и возможностями. Когда в этом уроке мы говорим «под капотом» — речь именно про Claude Code, не про браузерный claude.ai. И уж точно не про устройство языковых моделей: это другая тема.

1. Зачем заглядывать под капот

2 мая 2026 года я (Ирина) обнаружила, что у Claude Code на моём компьютере уже два месяца работает Auto-memory — встроенная память агента про меня, которая ведёт сам Claude Code в фоне. Я о ней не знала. Параллельно вела свой ручной файл-оглавление памяти и учила в курсе делать так же. Этот случай показал важную вещь: можно использовать Claude Code каждый день и не знать половины того, что в нём встроено. И это нормально — Anthropic не каждую новинку громко рекламирует, документация раскидана. Просто стоит хотя бы раз пройтись по карте, чтобы знать, какие кнопки есть на приборной панели. Подробный разбор этого кейса с Auto-memory — в Уроке 5+ «Карта памяти агента».

Системный фикс — ежедневный мониторинг обновлений Anthropic. После случая с Auto-memory мы поставили простой скрипт-наблюдатель, который раз в день в 9:00 утра автоматически проверяет 5 источников: GitHub releases Claude Code, anthropic.com/news, claude.com/blog, страницу changelog в продукте, support release notes. Если появились новые записи — присылает уведомление в Telegram коротким списком. Если новинок нет — молча выходит, не спамит (например, сегодня 3 мая ничего нового не было — и сообщения не пришло). Так мы больше не пропустим следующее «новое из коробки» на 38 дней. Скрипт у нас называется anthropic-changelog-watch.mjs, запускается через launchd (системный планировщик macOS) — это и есть пример сценария «системный фикс по корневой причине», который мы разбирали в Уроке 11 «Сценарии — автоматический режим».

Главная модель урока: рельсы Anthropic + наше наполнение

Когда я говорю «встроенное в Claude Code» — это не отдельные кнопки, которые работают сами. Это рельсы, на которых едут наши поезда. Anthropic даёт механизм, мы наполняем его содержимым:

  • Хуки — рельсы: триггеры PreToolUse / PostToolUse / UserPromptSubmit / SessionStart и формат настройки в settings.json. Наше наполнение: 47 наших sh-скриптов вроде protect-settings.sh, которые ловят моменты и проверяют
  • Skills — рельсы: формат папки .claude/skills/<name>/SKILL.md с frontmatter. Наше наполнение: наши skills типа /reviews-weekly, /telegram-messaging
  • Auto-memory — рельсы: типизированные карточки + индекс в ~/.claude/projects/.../memory/. Наше наполнение: карточки про Ирину (Auto-memory ведёт сама — это редкий случай, когда наполнение не наше)
  • Permissions — рельсы: формат allow/deny в settings.json. Наше наполнение: наши списки запретов (git push --force, rm -rf, values.clear())
  • Backup — рельсы: встроенный .claude/backups/ (последние сессии для /rewind). Наше наполнение: не используем встроенное — написали свой scripts/backup-to-drive.mjs, потому что встроенное локальное (Mac полетит — теряем), а наше внешнее, на Google Drive, расширенное. Это редкий случай, когда мы осознанно отказались от встроенного наполнения

Без рельс наша надстройка нигде бы не жила. Хуки работают, потому что Claude Code их вызывает в нужные моменты. Skills работают, потому что Claude Code их подключает. Курс до сих пор шёл по нашим поездам (наше наполнение в каждой категории). Сегодня — карта рельс: что вообще доступно у Anthropic, и где у нас уже что-то едет, а где — пока пусто или мы выбрали своё.

Аналогия

Представьте офис, где Anthropic построил здание: коридоры, переговорные, кухню, кабинеты, ресепшен, серверную. Мы заехали, расставили мебель, повесили регламенты на стены, наняли людей — это наше наполнение. Урок 12 — экскурсия по самому зданию: какие есть помещения, что в каждом можно делать. Не «что мы туда поставили» (это были предыдущие уроки), а «что Anthropic вообще предоставил».

Кейс: Backup — когда мы осознанно отказались от встроенного наполнения

Из 15 категорий рельс — в 14-й мы сделали редкий выбор: отказались от встроенного наполнения и положили своё. Это полезный паттерн.

Что предлагает Anthropic из коробки. Папка .claude/backups/ — Claude Code сам сохраняет туда последние сессии, чтобы команда /rewind могла откатить файл к предыдущему состоянию. Это полезно внутри одной сессии: «отмени последнее действие». Хранится локально на вашем Mac.

Чего нам не хватало. Встроенный backup решает короткую задачу (отменить шаг внутри сессии). Но он не закрывает длинную задачу: «если Mac полетит, у меня осталась резервная копия рабочей папки на внешнем носителе». Локальный бэкап на самом же Mac — не страховка от потери Mac.

Что сделали. Написали свой скрипт scripts/backup-to-drive.mjs, который раз в неделю (суббота 11:00 через launchd) архивирует ядро рабочей папки и заливает на Google Drive в отдельную папку. Архив включает: scripts/, memory/ (без транскриптов), telegram-bot/ без node_modules, .claude/rules + .claude/hooks, Auto-memory из ~/.claude/projects/.../memory/. Размер архива ~1.2 ГБ, версия каждой недели остаётся отдельным файлом — можно откатиться на месяц назад.

Что не делали и почему. Встроенный .claude/backups/ мы не отключали — пусть работает для команды /rewind, она ничему не мешает. Просто не полагаемся на неё как на единственный backup. Это тонкость осознанного выбора: встроенное оставляем работать в его задаче, а свою — закрываем своим решением.

Урок паттерна для вас. Когда смотрите на встроенную рельсу: (1) поняли её задачу — что Anthropic решал? (2) совпадает ли с вашей задачей? (3) если совпадает — наполняйте встроенное, не плодите дубль. (4) если не совпадает — пишите своё, но осознанно, понимая что встроенное закрывает. Иначе получите два конкурирующих решения, которые расходятся со временем (Камень 2 в Уроке 5+).

3. Auto-memory — личная память агента про вас

Что это. Встроенная папка-память на вашем Mac (~/.claude/projects/<путь-проекта>/memory/), в которую Claude Code сам пишет факты о вас, ваших правилах, проектах. Память переживает закрытие сессии — агент помнит, кто вы и какие у вас предпочтения, без вашего участия.

Подробный разбор — что и куда пишется, кто ведёт, как меняется, плюс наша история «38 дней не знала» с полным таймлайном — в Уроке 5+ «Карта памяти агента» (Глава 2 + врезка «Наш опыт»). Здесь, в Уроке 12, — только то, что специфично для нашей темы: место Auto-memory среди пяти встроенных механизмов и контраст с нашей надстройкой регламентов.

Что было бы без Auto-memory и без вашей системы регламентов

Auto-memory — про вас. on_demand_rules + skills + playbooks — про работу. Это разные слои, и без каждого ломается своё:

Что было бы без Auto-memory Что было бы без on_demand_rules / skills / playbooks
Каждое утро агент заново узнаёт, кто вы и какие у вас предпочтения. Лечится одним стартовым промптом: «привет, я CMO, не люблю длинные ответы» Skills (/reviews-weekly, /telegram-messaging) не запускались бы — каждую процедуру пришлось бы объяснять с нуля
Невозможно «забудь, что я тебе говорил про X»: разговор есть, но не зафиксирован как факт. Лечится явным «запомни» Playbooks (как делать недельный отчёт, как разбирать встречу) — не было бы алгоритма, каждая задача шла бы как первая
Между сессиями теряется тонкая обратная связь («не упоминай руководителей в ответах на отзывы»). Лечится повторением правки 1-2 раза on_demand_rules.md — каждое утро вы бы заново объясняли «что делать с отзывами», «как готовится дайджест»
STATE.yaml и handoff — слой между сессиями (Урок 2), они ортогональны и Auto-memory, и регламентам. Без них теряется передача смены

Связь с темой урока. Именно с Auto-memory у нас случился кейс 38-дневного незнания: встроенная рельса работала в фоне, я о ней не знала, учила учеников делать руками поверх. Этот класс ошибок — «строить надстройку поверх того, что уже встроено» — и есть главная боль, от которой защищает Урок 12. Карта 15 категорий рельс в Секции 2 — чтобы вы хотя бы раз прошлись и знали, что у вас уже есть из коробки и где наполнение Anthropic, а где ваше.

4. Permissions — разрешения на действия

Что это. Когда агент хочет сделать что-то на вашем компьютере (открыть файл, запустить команду в терминале, обратиться к внешней системе), Claude Code спрашивает разрешение: «можно?». Без этой защиты агент мог бы сделать что угодно за миллисекунду. Permissions — это списки «разрешено по умолчанию» и «запрещено навсегда», чтобы вы не нажимали «да-да-да» на каждый шаг.

Где живёт. В вашей рабочей папке есть скрытая папка .claude/. Внутри — два файла настроек:

Файл Назначение Кто видит
settings.json Общие настройки команды или проекта Все, кто работает с этой папкой
settings.local.json Личные настройки только для вашего компьютера Только вы (не уходит в общий доступ)

Внутри каждого — три блока: permissions (что можно/нельзя), hooks (мы их разбирали в Уроке 5), env (переменные окружения, например пути к внешним программам).

Как пощупать. Скажите агенту: «открой файл .claude/settings.local.json и покажи блок permissions». Вы увидите два списка: allow (разрешено без вопросов) и deny (запрещено всегда, даже если попросите). Например, у меня в deny стоит запрет на git push --force — это не отменишь без явного редактирования файла, и это правильно: такие операции необратимы.

Когда возникают запросы и кто ставит правила

Запрос на разрешение появляется в трёх случаях: (а) агент хочет запустить команду в терминале (открыть файл, выполнить скрипт, поработать с системой), (б) агент хочет обратиться к внешнему сервису через коннектор — мост к стороннему API или базе через MCP-сервер (подробно про коннекторы — в Уроке 6), (в) агент хочет изменить файл, который раньше не трогал. Если действие в списке allow — выполняется молча. Если в deny — отказ без обсуждения. Если ни там, ни там — открывается окно «можно?» с кнопками «разрешить раз», «всегда разрешать», «никогда не разрешать».

Кто формирует эти списки — четыре источника, в порядке приоритета:

  1. Anthropic кладёт базовые запреты по умолчанию (опасные системные команды) — это вшито в Claude Code, не редактируется
  2. Cowork при установке добавляет свои правила — наши общие настройки безопасности для всех, кто работает через нашу подписку
  3. Мы с вами добавляем при настройке агента — это и есть содержимое settings.json в рабочей папке
  4. Вы лично через кнопку «всегда разрешать» в момент запроса — это попадает в settings.local.json (видите только вы)

Как это устроено в нашей рабочей папке: в deny — операции, после которых работу не вернёшь (git push --force, rm -rf, values.clear() для Google Sheets — последняя добавлена после катастрофы 19.03, когда я случайно затёрла лист с формулами Ирины). В allow — частые рабочие команды, которые не опасны (git status, чтение файлов проекта, запуск наших скриптов в папке scripts/). Когда у вас появится свой агент — стартовый набор будет похожим, и вы будете дополнять под свои задачи: разрешать частое, запрещать необратимое.

Опасная кнопка

Флаг --dangerously-skip-permissions

У Claude Code есть флаг запуска, который отключает все разрешения сразу — агент не спрашивает ни о чём и делает всё подряд. Он нужен для автоматических сценариев, где разговаривать некому (например, наш claude_loop, см. ниже). В обычной интерактивной работе он не нужен и опасен. Если кто-то решит «давайте включим, чтобы не отвлекало» — это значит человек не понял, зачем permissions существуют. Запускать с этим флагом можно только то, что заранее ограничено deny-списком и работает в изолированной папке.

Где у нас используется флаг. Только в одном месте — в claude_loop у Ли. Это bash-скрипт, который запускает Claude CLI с этим флагом в фоне, чтобы Telegram-бот «Ли» мог сам отвечать на сообщения. Никто из людей в этот режим руками не лезет — туда уходят только сообщения через бот, и работает он в той же рабочей папке с ограничениями (запрещены git push --force, rm -rf, перетирание Google Sheets). В терминальной работе со мной флаг не используется — я каждый раз спрашиваю разрешение или беру его из allow-списка.

5. Под-агенты — отдельный мозг под тяжёлую задачу

Что это. Иногда задача требует прочитать 50 файлов или сделать большой веб-поиск. Если делать это в основном разговоре — вся прочитанная информация остаётся в памяти текущей сессии и забивает контекст: лимит токенов кончается быстрее, ответы становятся медленнее. Под-агент — это способ выделить тяжёлую часть в отдельный «контейнер», где он сделает работу, вернёт короткий ответ — и забудет всё лишнее.

Аналогия

Представьте, что у вас на столе один блокнот, и в нём вы держите все рабочие задачи. Если попросить коллегу «найди мне в архиве все договоры за 2024 год и скажи общую сумму» — он принесёт цифру, а не целый шкаф архива на стол. Под-агент работает так же: уходит в отдельную комнату, делает грязную работу, возвращается с результатом.

Готовые типы под-агентов в реальной работе. Это ревизия — список с пояснением, чтобы вы видели полную картину. Все они встроенные: либо из коробки Claude Code, либо из плагинов Anthropic. Своих кастомных в активной работе у нас сейчас нет (про это — честно ниже).

Под-агент Откуда Когда вызывается
Explore Anthropic, из коробки Быстрый поиск в коде или папке: «найди все упоминания Камилы в правилах»
Plan Anthropic, из коробки Построение плана работы перед сложной задачей
general-purpose Anthropic, из коробки Универсальный исследователь — для веб-поиска и многошаговых задач
claude-code-guide Плагин Anthropic Skills Ответы на вопросы про сам Claude Code: фичи, хуки, slash-команды
statusline-setup Плагин Anthropic Skills Настройка строки статуса (нижняя панель терминала)

Честно про кастомных под-агентов: пока не получилось

Мы делали два эксперимента — content-director под лендинг курса и smm-manager под SMM-задачи. Оба не прижились в практике. Первый отключили как неэффективный, второй ни разу не вызвали в реальной работе.

Почему. Кастомный под-агент полезен в паттерне «отдай ТЗ → получи готовый артефакт». А наша реальная работа — итеративная: я правлю → Ирина читает → даёт фидбек → я правлю снова. Под-агенту в этом потоке места нет — он не видит наш диалог в реальном времени, и каждый раз передавать ему контекст вручную неудобнее, чем работать напрямую.

Когда найдём паттерн, в котором кастомный под-агент даст реальную пользу — поделимся опытом отдельным материалом. Создание своих под-агентов — большая отдельная тема, и без живых кейсов рассказывать о ней — теория ради теории. Пока что у вас на старте достаточно встроенных пяти.

Как посмотреть что есть у вас. Откройте своего агента и попросите: «покажи список доступных под-агентов и где они лежат». Часть будет в .claude/agents/ в рабочей папке (это локальные, специально под ваши задачи), часть — в глобальной папке ~/.claude/agents/ (доступны всем сессиям), часть — встроенные Claude Code и плагины. Если список длиннее пяти-шести пунктов, и вы не помните, что они делают, — это сигнал провести ревизию: оставить нужное, остальное архивировать.

Как вызвать. Имена под-агентов знать не нужно — формулируйте задачу естественно: «найди у нас правила про отзывы», «сделай ресёрч на тему X», «прочитай этот файл и верни сводку». Агент сам решает, нужен ли тут под-агент и какой именно. Ваше дело — задача и критерии. Если хотите принудительно — можно сказать «отдай это под-агенту», но обычно агент справляется без подсказок.

Когда вызывать. Три признака, что задача — для под-агента:

  1. Нужно прочитать много файлов и вернуть короткий вывод
  2. Нужно веб-исследование (несколько сайтов, статьи, документация)
  3. Нужна отдельная пара глаз на готовый результат — например, ревизор перед публикацией

6. Plan Mode и Worktrees — режимы работы

Plan Mode — план перед действием

Что это. Встроенный в Claude Code режим, в котором агент сначала пишет план по задаче — что собирается сделать, в каком порядке, какие файлы тронет — и только после вашего «ок» начинает работать. Без Plan Mode агент может броситься делать сразу: иногда правильно, иногда нет, и тогда вы ловите проблему уже в готовом результате.

Как включать. Сочетанием Shift+Tab в окне терминала Claude Code — нажимаете и переключаетесь между обычным режимом, Auto-accept и Plan Mode. Текущий режим виден внизу терминала. Пока Plan Mode активен — перед каждым действием появляется пауза с планом и кнопкой «approve».

Plan Mode и наши стадии S1–S7 — в чём разница

В Уроке 8 мы разобрали наши стадии S1–S7 (классификатор → критик-вход → планировщик → вспоминатель → исполнитель → критик-выход → архиватор). Plan Mode тоже про «подумать перед действием», но это другой инструмент:

Plan Mode (встроенный) Наши стадии S1–S7
Глубина Один план перед действием Семь шагов с раздельной ответственностью каждого
Принудительность Включаешь сам, можно забыть Хук блокирует действие если стадии не заполнены — забыть нельзя
След План в чате, исчезает с историей Стадии в файле /tmp/li-stages.json — можно посмотреть позже
Кому подходит Любой пользователь Claude Code, с первого дня Зрелая система с хуками — у энтузиаста появляется на втором месяце работы

Как использую сама. Я в обычной работе не включаю Plan Mode отдельно. Каждая значимая задача у меня принудительно проходит через хук pre-task-stages-check.sh: если я не заполнила /tmp/li-stages.json с описанием S1–S4 (постановка, риски, автономия, контекст) — следующее действие блокируется. Plan Mode у меня встроен в этот хук на более глубоком уровне, поэтому отдельная команда не нужна.

Что значит для энтузиаста. Пока ваша система ещё растёт и хуков нет — Plan Mode даёт минимальную защиту от «бросилась делать». Включайте на сложных задачах: правка нескольких файлов, действия в Sheets, отправка в групповой чат. Когда наработаете опыт и поставите свои хуки — переключитесь на полную систему стадий, как у нас.

Worktrees — песочница для одной сессии (только Desktop)

Что это и для чего. Когда вы запускаете в Claude Code Desktop большую и рискованную задачу (правка многих файлов, эксперимент с новой структурой), есть страх «вдруг агент сломает текущую работу». Worktree — это отдельная копия вашей рабочей папки, в которой агент работает как будто в песочнице. Пока вы там — оригинал не меняется. Если эксперимент удался — переносите изменения в основную папку (это и есть «мерж» — слияние двух веток в одну). Если нет — закрываете и оригинал не пострадал.

Где встретить. При запуске сессии в Claude Code Desktop у некоторых версий есть выбор: «обычный режим» / «работать в worktree». Это и есть тот самый момент, в который легко промахнуться: видите две кнопки, не понимаете разницу, выбираете worktree — и оказываетесь в копии папки, не в оригинале.

Если вы случайно выбрали worktree и не поняли что происходит

Не паникуйте — оригинальная папка не тронута. Что бы агент ни сделал в worktree, всё это в копии. Просто закройте сессию и откройте новую в обычном режиме — увидите свою прежнюю папку нетронутой. Это и есть смысл worktree: песочница, в которой не страшно что-то сломать.

Когда стоит выбирать worktree сознательно. Когда задача рискованная и вы хотите попробовать «как будто» — переименовать структуру папок, поменять архитектуру, провести большой рефакторинг. Если результат нравится — переносите в оригинал. Если нет — выкидываете worktree, ничего не теряете.

Когда не стоит. В обычной ежедневной работе с привычными правками. Worktree усложняет: после сессии файлы лежат в копии, и нужно отдельно решать «забирать в оригинал или выкинуть». Для энтузиаста на старте — обычный режим без worktree, и так всё хорошо.

Особенность нашей подписки Cowork. У меня (Ирининого агента Ли в Cowork) Claude Code Desktop всегда создаёт worktree для каждой сессии — это отключить нельзя, особенность Cowork. Поэтому в нашем CLAUDE.md есть правило «работай через абсолютные пути»: в копии папки нет наших файлов в привычных местах, все пути нужно указывать полностью от корня. Если вы работаете НЕ через Cowork (например, через обычную подписку Claude Code) — у вас worktree включается только когда вы сами его выбрали.

7. Камни: чего не делать с этими механизмами

Камень 1. Включить «опасную кнопку» permissions без подготовки

Самая частая ошибка — раздражение «снова спрашивает» и включение --dangerously-skip-permissions «чтобы не отвлекало». В этот момент агент перестаёт быть управляемым: один неаккуратный запрос — и вы потеряли важный файл. Правильный путь: добавить часто разрешаемое в allow-список (тогда не будет запрашивать, но опасные команды останутся под защитой), а не отключать защиту целиком.

Камень 2. Запускать пять под-агентов на тяжёлой модели подряд

Каждый под-агент — отдельная мини-сессия, которая жжёт ваш токен-лимит. Шесть под-агентов на самой мощной модели за час однажды стоили мне рабочего вечера: лимит закончился, нужно было ждать. Правильный путь: группируйте задачи под одного под-агента, ставьте простые задачи на быструю/дешёвую модель, под-агентов на самой мощной модели держите для действительно сложных задач.

Как технически переключить под-агента на дешёвую модель — пригодится, когда у вас появится свой кастомный. В файле кастомного под-агента (.claude/agents/<имя>.md) сверху есть «шапка» с настройками — там поле model:

---
name: мой-под-агент
model: sonnet      # вот это поле
tools: Read, Bash
---

Поставили sonnet — все вызовы этого агента пойдут на Sonnet (по сравнению с Opus примерно в пять раз дешевле). Можно поставить haiku для совсем простых поисковых задач — ещё дешевле. Если поле не указано — берётся модель родительской сессии. Для встроенных под-агентов (Explore, Plan, general-purpose) Anthropic сам ставит разумные дефолты — обычно не самую тяжёлую модель.

Камень 3. Не понимать, что Plan Mode и стадии — об одном

Иногда у новичков складывается ощущение «вот наша система стадий, а Plan Mode — это другое, его тоже надо учить». На самом деле обе вещи решают одну задачу: заставить агента подумать перед действием. Plan Mode — встроенная упрощённая версия, наши стадии S1–S7 — расширенная и принудительная через хуки. Они сосуществуют, не конкурируют. На простой задаче хватит Plan Mode; на регулярной рабочей — наша система стадий с записью bugs-log.

Камень 4. Думать, что Auto-memory заменит нашу систему регламентов

Auto-memory — про вас: ваш стиль, ваши правила общения, ваши проекты на уровне фактов. Наша система регламентов (CLAUDE.md, on_demand_rules.md, skills, playbooks) — про работу: процессы, чек-листы, защиту от ошибок. Это разные слои. Не пытайтесь перенести бизнес-процессы в Auto-memory — там они потеряются среди личных записей. И наоборот: не записывайте «мне нравится короткий тон» в наш CLAUDE.md — это не правило процесса.

8. Практика: 15 минут на инвентаризацию

Цель — пощупать руками 4 категории, которые мы детально разобрали в этом уроке (Auto-memory, Permissions, Под-агенты, Plan Mode). Worktree пощупать нельзя «вручную», он работает в фоне.

Если у вас уже есть свой агент

  • Спросите агента: «Покажи мою папку ~/.claude/projects/». Откройте в файловом менеджере. Найдите подпапку memory/ внутри своего проекта. Посмотрите, какие там файлы и что в них
  • Скажите агенту: «Открой .claude/settings.local.json и покажи блок permissions». Прочитайте список allow и deny. Спросите себя: что-то здесь кажется лишним или опасным?
  • Дайте агенту простую задачу: «Через под-агента Explore найди все упоминания моего имени в моих правилах». Заметьте, что обычная сессия не загружается результатами поиска — пришёл только короткий ответ
  • На следующей сложной задаче (правка нескольких файлов или новый отчёт) включите Plan Mode: «Сделай план перед действием». Сравните ощущение с обычным режимом

Если агента ещё нет

  • Откройте на компьютере папку ~/.claude/ (через Finder, Shift+Cmd+G). Если её нет — это нормально, она появится после первого запуска Claude Code
  • Запишите на отдельной странице, какие из 15 категорий рельс (карта в Секции 2) вам особенно нужны на старте. Например: «у меня много сложных задач — начну с Plan Mode», «не хочу терять заметки между сессиями — посмотрю на Auto-memory в первый день», «нужно подключить Telegram — копну MCP / коннекторы»
  • Когда будете запускать первого агента — на первом часе работы пройдитесь по этому уроку и пощупайте каждое

✅ Закрепить в CLAUDE.md

Знание из урока становится правилом агента только когда записано в CLAUDE.md. Без этого шага вы продолжите включать опасные флаги «потому что отвлекает», а под-агентов будете запускать вслепую — и потеряете лимит за час.

Действие на 2 минуты. Откройте своего агента и скажите:

«Я прошёл Урок 12 "Под капотом Claude Code". Добавь в CLAUDE.md правило: (1) флаг --dangerously-skip-permissions использовать только в автоматических сценариях, не в интерактивной работе; (2) тяжёлые задачи (чтение многих файлов, веб-поиск) — через под-агента, не в основном контексте; (3) перед сложной задачей с правкой нескольких файлов — включать Plan Mode или проходить наши стадии S1–S2.»

Проверка: откройте CLAUDE.md, убедитесь что правило добавлено. Если нет — повторите запрос конкретнее.

10. Шпаргалка

Три вещи, которые обязательно уйдут с вами из урока

  • 15 категорий рельс Anthropic — карта того, что у вас уже есть из коробки. Память (Auto-memory), Skills, Под-агенты, Хуки, Slash-команды, Расписания, Plan Mode, Plugins, MCP, IDE, Модели, Tool use, Project structure, Backup & Security, Экосистема. Не все сразу нужны, но знать, что они есть — обязательно. Иначе риск 38-дневного незнания, как у нас с Auto-memory.
  • Модель «рельсы + наполнение». Anthropic даёт механизм (рельсы), мы кладём содержимое (поезда). Хуки — рельсы, наши 47 sh-скриптов — поезда. Skills — рельсы, наш /reviews-weekly — поезд. Прежде чем строить надстройку — посмотрите, нет ли рельсы под вашу задачу. Если есть — наполняйте её, не плодите дубль. Если решаете уйти от встроенного — делайте осознанно (как мы с Backup, см. кейс в Секции 2).
  • Опасные кнопки трогать только осознанно. Флаг --dangerously-skip-permissions, прямое редактирование Auto-memory, запуск пяти тяжёлых под-агентов подряд — всё это работающие механизмы, но без понимания они стоят денег и времени.

Как проверить что урок усвоен

Если вы (а) знаете, в какой папке на вашем компьютере живёт Auto-memory; (б) умеете показать в settings свой allow-список; (в) на следующей сложной задаче включили Plan Mode сами без напоминания — урок усвоен.
