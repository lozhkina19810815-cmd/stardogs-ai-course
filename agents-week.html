Agents Week 2026
Яндекс Образование

Разбор 5 дней курса • Что применимо, что оверинжиниринг

5-дневный курс Яндекс Образования для инженеров, строящих ИИ-агентов. Мы проходили его параллельно с нашей реальной работой, чтобы понять: что у нас уже есть, чего не хватает, что — избыточно для нашего масштаба.

Общий вывод

Курс рассчитан на тех, кто НАЧИНАЕТ строить агентов. У нас уже работающая система: модель + промпты + инструменты + память + guardrails + workflow + мультиагентность. Мы не целевая аудитория — мы практики.

Но курс полезен как язык: он даёт терминологию, которой мы раньше не пользовались, но которая описывает то, что мы уже делаем интуитивно. Это пригодится при разговорах с инженерами и в документации.

По каждому дню

День 1

Intro + Tools + MCP

В курсе: LLM как мозг, токенизация, tool calling, MCP-протокол
У нас: Claude Opus 4.6, скрипты, Plane MCP, Telegram MCP
Базу знаем. Полезно как язык — чтобы говорить с инженерами на одном языке.
День 2

Memory + Guardrails

В курсе: краткосрочная / долгосрочная память, RAG, PII маскирование, prompt injection detection, human-in-the-loop
У нас: STATE, handoffs, MEMORY, playbooks, rules, bugs-log, enrichment-digest. Hooks на выходе. Подтверждение отправок.
Память — наша сильная сторона, мы далеко впереди курса. Пробел: input guardrails — нет детекции prompt injection в Telegram. Единственное, что реально стоит внедрить.
День 3

Workflow + Multi-Agent + Multimodality

В курсе: ReAct, Plan-and-Execute, Reflection, CrewAI, LangGraph, vision / audio
У нас: workflow S1–S7, loop-агент + терминальный + субагенты, Groq Vision, Whisper, Fathom
Паттерны (ReAct, Plan-and-Execute) полезны как ЯЗЫК для описания того, что мы уже делаем. Наш S1–S7 — это по сути Plan-and-Execute с Reflection на стадии S6.
День 4

Evaluation

В курсе: completion rate, override rate, τ-bench, LLM-as-Judge, regression suites, CI/CD gates
У нас: bugs-log (ручной), прямая обратная связь от Ирины, skill /review
Метрики решают проблему, которой у нас нет. У нас 1 пользователь + 1 агент + прямая обратная связь. Ирина и так знает, где агент лажает — не по графикам, а по опыту. Для нас — оверинжиниринг.
День 5

Production Engineering

В курсе: tracing (Langfuse, LangSmith), scaling, retries / fallbacks / circuit breakers, caching, cost management
У нас: watchdog, launchd, heartbeat, routing между моделями
Production-инженерия для систем с тысячами пользователей. У нас один пользователь. Tracing, semantic caching, circuit breakers — оверинжиниринг для нашего масштаба.

Жёсткая оценка: что реально полезно

✅ Полезно — внедрять

  • Input guardrails — детекция prompt injection в чатах. Единственное, что реально защищает от атак на агента через сообщения пользователей. Можно сделать дешёвым классификатором.

📖 Полезно как знание

  • Паттерны workflow (ReAct, Plan-and-Execute, Reflection) — язык для описания нашей архитектуры
  • Архитектура агента (модель + промпты + tools + память + guardrails) — подтверждение, что мы всё собрали правильно
  • MCP — знаем, используем. Можно расширить

⛔ Оверинжиниринг для нашего масштаба

  • Формальные метрики (completion rate, override rate) — мы видим качество напрямую
  • Tracing / observability (Langfuse и т.п.) — не нужны при одном пользователе
  • Semantic caching — нет повторяющихся запросов
  • Circuit breaker — watchdog уже перезапускает
  • CI/CD для промптов — git + CLAUDE.md достаточно
  • Regression suites — bugs-log + guards достаточно

Главный инсайт

Курс подтверждает: мы построили production-ready агента интуитивно, без формального обучения. Архитектура соответствует тому, чему учат инженеров Яндекса. Разница — в масштабе. Их инструменты (Langfuse, τ-bench, CI/CD gates) решают проблемы масштаба, которых у нас нет.

Наша реальная зона роста — не инструменты из курса, а дисциплина исполнения. Это не решается ни метриками, ни tracing — это решается тем, что агент лучше следит за собой.
