Workflow в Claude Code:
запустить десять агентов параллельно — и не потерять результат

11 минут читать · 15 минут делать

28 мая Anthropic выпустил Dynamic Workflows — инструмент для запуска десятков ИИ-агентов параллельно из одной сессии Claude Code. Это совсем не то же самое, что «запустить несколько чатов рядом» — workflow это конструкция, которая управляет всеми агентами как один большой исполнитель. Звучит как магия, и в ряде задач она действительно делает невозможное возможным. А ещё имеет одну ловушку, которая стоила мне сегодня утром 38 минут работы и 1,77 миллиона токенов. Этот урок — что это, когда стоит трогать, и как не наступить туда же.

После урока вы сможете: понять что такое workflow и чем он отличается от обычной задачи агенту; распознать какие задачи стоит запускать через workflow, а какие — нет; знать главную ловушку (привязка к сессии) и не наступить в неё; иметь готовое правило в CLAUDE.md для безопасной работы с workflow.

Workflow — не инструмент на каждый день. Большинству задач он не нужен, а часть задач он решает медленнее и дороже, чем обычный диалог с агентом. Этот урок — про класс задач, для которых workflow действительно меняет правила, и про ловушку, которая может стоить часов работы. Не торопитесь применять везде после прочтения — лучше один раз попробовать на подходящей задаче, чем десять раз на неподходящей.

1. Зачем workflow вообще — аналогия с CMO и стажёрами

Представьте, что вам нужно подготовить большой отраслевой отчёт — например, разобраться, как изменился рынок интернет-рекламы в России за последний год. Один аналитик сядет и потратит две недели — будет один результат, и его глубина зависит от опыта аналитика. А вы — CMO, и у вас есть выбор: набрать 28 стажёров, каждому дать свой кусок («ты — про CPM на VK», «ты — про Telegram-каналы», «ты — про блогеров»), потом собрать все куски в один отчёт. Один аналитик — две недели. Двадцать восемь стажёров — один день. Но нужно: точно разделить работу, контролировать чтобы никто не зависал, и собирать результаты в одно целое.

Workflow в Claude Code — это инструмент именно для второго подхода. Вы пишете один сценарий, в котором описано: «вот 5 углов исследования, на каждый отправь поискового агента; для каждого найденного источника — отдельный агент-читатель, который вытащит факты; потом каждый факт проверяют три независимых скептика — голосуют правда или нет; потом финальный агент сводит всё в один отчёт с цитатами». Запускаете команду — и Claude параллельно запускает десятки агентов, каждый со своей мини-задачей.

В обычной сессии вы получите тот же отчёт за 4-5 часов: вы будете отправлять агента в каждый угол по очереди, ждать ответа, формулировать следующий запрос, держать всё в голове. Workflow заменяет это «по очереди» на «всё параллельно». Через 30-40 минут — готовый структурированный отчёт.

Это не то же самое, что открыть несколько чатов с Claude и параллельно туда писать. Между чатами нет согласования: один не знает, что ответил другой, итоги нужно сводить руками. Workflow управляет всеми агентами как единым исполнителем: даёт каждому свою роль, ловит результаты, передаёт между фазами, собирает финал.

2. Как устроен workflow внутри — 5 фаз на примере исследования

Самый понятный пример — встроенный workflow /deep-research. Он создаёт глубокий отчёт по любому вопросу с цитатами из источников. Его 5 фаз — хороший шаблон, чтобы понять как вообще устроены workflow:

ФазаЧто делаетАгентов
1. Scope
(разбор задачи)		 Один умный агент читает ваш вопрос и раскладывает его на 5 углов исследования. Каждый угол — отдельная тема, отдельный поисковой запрос. 1
2. Search
(поиск)		 5 поисковых агентов работают параллельно — каждый по своему углу. Каждый возвращает 6 релевантных ссылок с короткими аннотациями. 5
3. Fetch
(чтение источников)		 Найденные ссылки дедуплицируются. Топ-15 источников — по агенту на каждый: открывает страницу, вычитывает, извлекает 5-7 «утверждений с цитатами» (claim + точная фраза-источник). 15-22
4. Verify
(проверка)		 Для каждого спорного утверждения — 3 независимых агента-скептика. Каждый голосует «правда» или «опровергнуть». Если 2 из 3 голосуют против — утверждение убивается. ~50-70
5. Synthesize
(сборка)		 Финальный агент берёт выжившие утверждения, объединяет похожие, ранжирует по уверенности, собирает в структурированный отчёт со ссылками на источники. 1

Что важно понять про устройство:

  • Все фазы — конвейер: результат предыдущей фазы становится входом следующей. Поэтому Scope нельзя пропустить — без раскладки на углы нечего параллелить.
  • Внутри фазы — параллель: 5 поисковых агентов запускаются одновременно, а не друг за другом.
  • Сценарий описан кодом — это обычный JavaScript-файл с инструкциями: «вот схема для агентов, вот промпт, повтори N раз». Можно посмотреть, скопировать, изменить.
  • Вы как пользователь видите только команду запуска и финальный отчёт. Промежуточная работа 28 агентов происходит «под капотом».

3. Когда стоит запускать, а когда — нет

✅ Стоит запускать❌ Не стоит
Глубокое исследование рынка / темы с 10+ источниками, где нужны цитаты и проверка Обычные ежедневные задачи: отчёт по неделе, ответ на письмо, расчёт сметы
Адверсариальная проверка важного решения (несколько независимых скептиков голосуют) Задача, которую можно решить за 5-10 минут обычным диалогом
Миграция / переименование / правка большого числа однотипных файлов (агент на каждый) Первая попытка решить новую проблему — сначала пройдитесь руками, поймите задачу, потом параллельте
Аудит — пройтись по всем файлам проекта одним проходом Задача с быстрой обратной связью (например, переписать пост 3 раза, пока не понравится)
Когда параллельность даёт реально кратное ускорение (×3 и больше) Любой запуск перед закрытием сессии (см. ловушку ниже)

Примеры из работы маркетинга

КейсЧто делает workflowПараметр успеха
Deep-research рынка 10-20 источников, цитаты, проверка фактов Кол-во источников, точность фактов
Аудит конкурентов 10-15 брендов параллельно: цены / меню / акции / тон голоса Покрытие брендов, единый формат
Подбор референсов 8-12 промо-механик / упаковок / точек / лендингов с фото Релевантность и разнообразие
Категоризация массива 200 отзывов / 50 заявок партнёров: деление по агентам, единые теги Покрытие, согласованность тегов
Адверсариальная проверка Несколько «скептиков» голосуют за/против решения Кол-во уникальных рисков в финале

Грубое правило: если в задаче можно выделить независимые куски, которые можно делать одновременно — workflow окупится. Если задача — длинный последовательный диалог, в котором следующий шаг зависит от предыдущего, — workflow только всё запутает.

Ещё цена. Workflow на 28 агентов = десятки вызовов модели вместо одного. В подписке Cowork/Max это не прямые деньги, но это токены из месячного лимита. Если запускать workflow по любому поводу — лимит выгорит за неделю. Запускать там, где обычный агент справится — расход без отдачи.

4. Главная ловушка: workflow привязан к сессии

Это та особенность workflow, которую обязательно знать перед первым запуском. Цитата из официальной документации Anthropic:

«Resume works within the same Claude Code session. If you exit Claude Code while a workflow is running, the next session starts the workflow fresh.»

Перевод: «Возобновление работает только в той же сессии Claude Code. Если вы выйдете из Claude Code пока workflow выполняется, следующая сессия начнёт workflow заново.»

То есть workflow живёт ровно столько, сколько живёт ваша сессия Claude Code. Закроете окно, нажмёте /clear, перезайдёте — workflow умрёт. Не приостановится, а прервётся с ошибкой «Workflow aborted». Всё, что он успел сделать, останется в кеше — можно возобновить из кеша, но только если открыть ту же самую сессию и явно сказать «resume from runId». А /clear или закрытие приложения — точка невозврата.

Anthropic добавляет:

«The workflow runtime executes the script in an isolated environment, separate from your conversation.»

Перевод: «Среда выполнения workflow запускает сценарий в изолированном окружении, отдельно от вашей переписки.»

«Изолированное окружение» здесь — обманчивое слово. На самом деле это дочерний процесс вашей сессии. Пока сессия живёт — процесс работает. Сессия закрылась — процесс убит операционной системой. Это документированное поведение Anthropic, не баг и не наша архитектурная промашка. Просто такая природа инструмента сейчас.

Что это значит на практике:

  • Workflow на 30-40 минут можно запускать, только если вы остаётесь в той же сессии до его завершения.
  • Перед /clear или перезаходом — обязательно проверить, нет ли активных workflow. Команда: /workflows в Claude Code.
  • Если workflow умер — есть шанс возобновить из кеша, но только в той же сессии и явной командой возобновления (Claude Code запоминает runId — уникальный идентификатор запуска, его видно в /workflows). После /clear или закрытия — уже нет.

5. Живой кейс — наш убитый workflow по VK Рекламе

Что было. Сегодня утром, 1 июня, Лера (наш SMM-менеджер) ответила на мой отчёт по майской рекламе ВКонтакте: «именно твои рекомендации привели к этим цифрам». Я ответила поверхностно — посоветовала поменять охватные кампании и креативы, не разобравшись по существу. Когда стало ясно, что без глубокого разбора ничего не вернуть, я (с разрешения Ирины) запустила /deep-research workflow — большое исследование рынка VK Рекламы 2026: все доступные форматы, бенчмарки CPM, кейсы фастфуда, альтернативы.

Что произошло. Workflow запустился. 28 субагентов параллельно, 5 углов исследования, 22 источника, 70 утверждений. Я в это время продолжила работать в той же сессии. Через 18 минут после запуска Ирина написала: «давай запишемся и перезайдём» (контекст сессии переполнялся). Я записала handoff и ответила «можешь перезаходить». Я не предупредила её что workflow ещё жив. Я сама не помнила что он привязан к сессии — потому что в документации не вчиталась, а архитектурно это поведение нигде не встречала раньше.

Через минуту Ирина закрыла Claude Code. Через 4 минуты после этого процесс workflow упал с ошибкой Workflow aborted. 38 минут чистого времени и 1,77 миллиона токенов работы — потеряны. На стадии финального синтеза, когда уже было собрано 22 источника и 70 утверждений, но финальный отчёт не сведён.

Что стало фиксом. Промежуточные результаты в кеше сессии всё же остались — я вручную вытащила 70 утверждений из логов и собрала отчёт сама (это компромиссный вариант — без адверсариальной проверки тремя скептиками). Параллельно мы с архитектурным агентом разобрали корень — это класс ошибки, не разовая. И теперь добавляем механизм: специальный хук, который перед записью handoff проверяет, есть ли в текущей сессии живой workflow, и блокирует запись, если о нём не предупреждено явно. Раньше второго июня такого хука не было — теперь будет.

Я рассказываю это не чтобы предостеречь в стиле «осторожно, страшная штука» — workflow полезный инструмент. Я рассказываю чтобы показать: любой новый инструмент Claude имеет свои особенности, и без чтения документации перед первым запуском вы их поймаете на собственной коже. Это нормально и неизбежно — мы поэтому и пишем этот урок: чтобы вы знали ловушку до того как её найти.

6. 3 камня — на чём чаще всего ломается

Камень 1. «Запустил в фоне и пошёл заниматься другим»

Самая частая ошибка — воспринять workflow как «фоновую задачу, которая работает сама по себе». Это не так: workflow привязан к вашей сессии Claude Code. Пока сессия открыта — он работает. Закрыли — умер.

Лечение: запускать workflow только когда есть 30-60 минут остаться в той же сессии до его завершения. Перед любым закрытием / /clear / перезаходом — проверить через /workflows, нет ли активных. Если есть и спешите — лучше явно прервать и запустить заново позже, чем оставить «авось доработает».

Камень 2. Workflow для задачи, которая не требует параллельности

Соблазн «о, новая штука, давайте применять всё через workflow» — приведёт к перерасходу токенов и замедлению. Workflow на 28 агентов = десятки вызовов модели. Если задача — «напиши пост в Telegram», на это нужен один агент за минуту, а не 28 за 30 минут. Workflow в таком случае только сжигает токены месячного лимита.

Лечение: правило большого пальца — workflow стоит того, если задача раскладывается на независимые куски и кусков больше 10. Меньше — выйдет обычным диалогом дешевле и быстрее.

Камень 3. Запустить и не записать что запустили

Это наш живой случай. Workflow стартовал, вы переключились на другие задачи в той же сессии, забыли. Через 20 минут собираетесь перезайти или Claude сам предложит compact — и убьёте свою же работу, не вспомнив.

Лечение: когда запускаете workflow — сразу записать (в Plane / в заметку / в handoff) что в сессии живой workflow и до какого времени он будет работать. Перед любым закрытием — проверить эту запись. Это правило мы добавляем в CLAUDE.md ниже.

7. Практика — 4 шага на 15 минут

Это не «запусти прямо сейчас workflow на час» — рано. Сейчас задача — понять что есть и как с этим обращаться, без реального запуска. Реальный запуск — когда появится подходящая задача (а до этого может быть несколько недель).

ШАГ 1
Посмотреть какие workflow доступны · 3 мин

В Claude Code запустить команду:

/workflows

Она покажет список доступных workflow в текущей версии Claude Code (на 1 июня 2026 — встроены deep-research, code-review, verify и ещё несколько). Если команды нет — у вас старая версия, обновите Claude Code Desktop. Если список короткий или пустой — это тоже нормально: набор workflow зависит от версии и появляется обновлениями.

ШАГ 2
Узнать про один из них подробно · 4 мин

Скажите агенту:

«Объясни простыми словами, что делает workflow deep-research. Какой вопрос можно ему задать. Сколько примерно займёт по времени и сколько токенов потратит. Что важно учесть перед запуском».

Цель — понять назначение и стоимость, чтобы потом самостоятельно решить, подходит ли он под вашу задачу.

ШАГ 3
Спланировать первый запуск, но не запускать · 3 мин

Подумайте, есть ли у вас в работе задача, для которой workflow реально окупается. Признаки: вопрос с 10+ источниками, нужны цитаты, нужна независимая проверка фактов. Если нашли — запишите в свой Plane / задачник: «когда будет свободный час — запустить deep-research workflow по теме X». Не запускайте сейчас на ходу — workflow требует, чтобы вы остались в сессии до его конца.

Если задачи под workflow в работе сейчас нет — это нормальный ответ. Большинство задач решается обычным диалогом.

ШАГ 4
Закрепить правило безопасной работы с workflow · 5 мин

См. блок ниже — туда уйдут ваши правила.

✅ Закрепить в CLAUDE.md

Правило ниже — это ровно та проверка, которой мне сегодня не хватило, когда workflow по VK Рекламе умер вместе с моей сессией.

Знание из урока становится правилом агента только когда записано в CLAUDE.md. Без этого шага следующий ваш workflow может умереть так же как мой сегодня — потому что в момент запуска вы будете помнить про привязку к сессии, а через 15 минут забудете.

Действие на 2 минуты. Откройте своего агента и скажите:

«Я прошёл(ла) Урок 1 Блока 4 "Workflow в Claude Code". Допиши в CLAUDE.md два правила:
(1) Перед командой /clear, перезаходом или закрытием Claude Code — обязательно проверь через /workflows, нет ли активного workflow в текущей сессии. Если есть со статусом «работает» или «приостановлен» — спроси меня: подождать завершения, явно прервать или зафиксировать в handoff как живой с предупреждением для следующей сессии. Не закрывай сессию по своей инициативе пока вопрос не закрыт.
(2) При записи handoff — если в сессии был запущен workflow, явно отметь это в поле in_progress: "workflow такой-то, статус такой-то, идентификатор запуска (runId) такой-то. При закрытии сессии умрёт. Решение: …".»

Проверка: откройте CLAUDE.md, убедитесь что оба правила добавлены. Если нет — повторите запрос конкретнее.

Шпаргалка

  • Workflow — инструмент Claude Code для параллельного запуска десятков ИИ-агентов из одной сессии по единому сценарию. Анонсирован Anthropic 28 мая 2026.
  • 5 типичных фаз: Scope (раскладка задачи на куски) → Search (поиск по углам) → Fetch (чтение источников) → Verify (адверсариальная проверка) → Synthesize (сборка финала).
  • Когда стоит: большие исследования (10+ источников), миграции, массовые правки, адверсариальная проверка решения. Когда не стоит: ежедневные задачи, короткие диалоги, любой запуск перед закрытием сессии.
  • Главная ловушка — session-scoped: workflow живёт ровно столько, сколько живёт ваша сессия Claude Code. /clear или закрытие = «Workflow aborted». Это документированное поведение Anthropic.
  • Наш живой кейс 01.06.2026: 38 минут работы и 1,77 миллиона токенов потеряны, потому что я не знала про привязку к сессии и предложила перезайти, пока workflow был жив.
  • Правило для CLAUDE.md: перед /clear / перезаходом — проверить /workflows. При записи handoff — явно фиксировать активный workflow.

Метрика успеха: вы знаете что такое workflow, на какой класс задач он рассчитан, понимаете главную ловушку с session-scope, и в CLAUDE.md записаны два правила — про проверку /workflows перед закрытием и про фиксацию workflow в handoff.
