Архитектура агента Ли

Как устроен наш работающий агент • Что можно перенять

Ли — ИИ-агент Ирины Ложкиной на базе Claude Code. Работает 2+ месяца, 160+ сессий, 50+ навыков. Здесь — наша текущая архитектура как референс: что есть, почему так, что из этого применимо каждому новому агенту энтузиаста.

Модель памяти — 5 типов

Память ИИ-агента не одна, а пять разных подсистем. Мы реализовали все пять. Каждая решает свою задачу и хранится по-разному.

Episodic (что случилось)

Handoffs, bugs-log, индекс сессий. История конкретных событий.

Semantic (что знаем)

Auto-memory от Anthropic (карточки про вас), STATE.yaml, карта чатов, карта людей. Факты и связи.

Procedural (как делать)

Playbooks, guards, hooks, skills. Процедуры и алгоритмы.

Working (текущее)

Контекст активной сессии Claude Code. Живёт только в пределах сессии.

Tool (какие инструменты)

On-demand rules, skills descriptions. Знание о том, что агент умеет и когда это использовать.

Главный цикл памяти: Episodic → Semantic → Procedural. Ошибка случилась (episodic) → превратилась в знание (semantic) → стала правилом для будущих сессий (procedural). Без этого цикла агент не учится.

Skills vs Playbooks — наше решение

Мы прошли через этап, когда всё было в playbooks. Сейчас пересматриваем: skill — это исполняемый промпт с CONTRACT, playbook — справочник.

  • Skill — принудительный чек-лист с блокирующим hook. Агент не может обойти.
  • Playbook — длинный текст с объяснением «почему» и описанием подводных камней. Агент читает как инструкцию.
  • Правило перехода: когда процесс стабилизировался (3+ успешных прогонов) — playbook повышается до skill.
  • Progressive disclosure: description skill'а (2 КБ) подгружается при старте, тело — только при триггере.

Фреймворк мышления: Голдратт TOC

В апреле мы положили в основу мышления агента Теорию ограничений Голдратта. Почему:

  • Текущее ограничение агента = качество постановки задач на входе (не контекст, не правила)
  • 3 системных нарушения: локальная оптимизация (много мелких правил), растущие запасы (мёртвые playbooks), инерция (правила для старых ограничений)
  • Метрики TOC: Проход (T) = принятые результаты, Запасы (I) = незавершённые задачи + мёртвые артефакты, OE = токены + время

Это даёт ответ на вопрос, который мы задавали себе месяцами: «Что улучшать в первую очередь?» — то, что является bottleneck'ом именно сейчас, а не всё сразу.

Системные проблемы, которые мы видим

Честный список открытых вопросов — чтобы новый энтузиаст знал заранее, что решено, а что нет.

  • Контекст не держится между сессиями — новая сессия не всегда находит нужные файлы в памяти. Решаем через task-manifest и queryable memory
  • Skills и playbooks параллельно — 8 skills + 30 playbooks, дублирование, миграция не завершена
  • Инерция правил — некоторые правила для старых ограничений до сих пор нагружают контекст каждую сессию
  • Ритм создания и архивации — нет формального механизма «удалить мёртвое». Правило: никогда не удалять, только архивировать

Ключевые архитектурные решения — хронология

  • Agent OS по Крол­у — правила в .claude/rules/, автозагрузка при старте сессии
  • CONTRACT — 50–150 токенов невытесняемых правил в каждом skill
  • Файловая память подтверждена — vector DB overhead не оправдан при 72 файлах
  • Skills > Playbooks — skill как исполняемый промпт с CONTRACT
  • Никогда не удалять — только архивировать. Правило Ирины
  • Голдратт TOC — фреймворк мышления для агента
  • Аудит skills через использование — не на бумаге, а по результатам
  • Bottom-up внедрение — 4 энтузиаста строят своих агентов параллельно

Что из этого переносится новому агенту

Когда энтузиаст создаёт своего агента, ему НЕ нужно повторять весь наш путь. Вот минимум, который мы рекомендуем собрать сразу:

  • CLAUDE.md с миссией, ограничениями и структурой памяти (минимум 20 строк, максимум 200)
  • 5 базовых guards — которые мы выделили из своих 30+ правил как универсальные
  • Механизм handoff между сессиями — чтобы контекст не терялся
  • Рабочая папка с правом чтения / записи
  • Hook на завершение сессии — блокирует выход без записанного контекста

Это стартовый пакет. Всё остальное (playbooks, skills, свои rules) — накапливается по мере работы, через еженедельную рефлексию и ежемесячные объединения.
